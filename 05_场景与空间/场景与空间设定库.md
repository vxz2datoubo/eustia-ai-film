# 场景与空间设定库

> 本文件维护固定场景的性质、材质、功能、氛围、固定结构、道具、光源、局部动线和场景资产关系。空间拓扑、相邻关系、入口、方向、桥路高低和真实可达路线的唯一权威为[00_项目地图文件](00_项目地图文件.md)。
> Scene / Camera Anchor / View / Media Asset / Media Version / Relation 的机器身份与命名统一服从 `../10_运行时/scene_asset_identity_schema.yaml`；版本与 locator 统一服从 `../10_运行时/scene_media_resolver_manifest.yaml`。
> Camera Anchor 中文名优先使用可读的**语义机位名**，不用流水号代替空间意义。

# 1. 世界空间总则

- 架空中世纪晚期空中都市底层。
- 中世纪手工时代材质，默认不出现现代物品、现代道路、电灯和开放天空。
- 底层城市被悬崖、岩壁和高墙包围；建筑比例、道路连通、楼层高低和相邻关系必须稳定。
- 场景是社会机制和权力结构，不只是装饰背景。

# 3. 莉莉会所｜EUS-SCN-000002

## 性质与社会功能

莉莉会所位于绯灯街继续向南一段的西侧，是绯灯街里体量较大、经营稳定的灰色歌舞娱乐场所。主体为旧欧洲中世纪晚期风格，不是现代夜店，也不是贵族宫廷；可少量使用帘幕、流苏、花格和深红木色细节。它表面承担喝酒、陪侍、歌舞和消遣，实际也是平民区交换消息、谈私活、结识熟人、临时藏身、上纳金和灰色人情流动的节点。

## 固定空间与动线

- 建筑位于绯灯街西侧，临街入口从东侧进入，室内主轴向西。
- 进门后左手为吧台、酒架、账本和接待区。
- 继续直行穿过帘幕后进入主大厅。
- 主大厅包含卡座、圆桌、舞台、钢管、笼台等活动空间；大厅左侧楼梯通往二楼。
- 二楼是带回廊的半私密办公 / 管事区域，可俯视大厅，处理账目、筛选客人和维持秩序。

# 4. 绯灯街｜EUS-SCN-000001

## 场景描述

中世纪平民区的狭长 S 形石板生活商业街，被高耸灰黑岩壁与悬崖包围。两侧密集排列约两至三层石木混构遗民建筑，蓝色、红褐、灰白墙面剥落，旧木窗、铁栏杆阳台、锈蚀支架和老式雨棚密布。硬面包铺、杂货摊、药铺、酒馆和住户混杂，窗台晾着粗布衣物，招牌陈旧发黑。路面由不规则石板与鹅卵石铺成，阴天自然漫射光下呈冷灰、棕灰、铁锈红、旧蓝与木褐色，暗部仍保留细节。远处不见开放天空，只见巨大垂直岩壁与灰雾，形成长期压迫感。这里既是贫民商业街，也是娼馆、医疗、仓储、装卸、酒馆和住房交叠的生存街区。

# 7. 市集与布道施粥广场 / 教堂钟楼｜EUS-SCN-000005

## 场景描述

天空牢狱下层平民区北端的公共市集与钟楼制度空间。广场由潮湿石板铺成，两侧分布棚位、推车、木桶、粮食与平民营生摊位，周边建筑仍是拥挤老旧的石木混构民居。钟楼位于广场北端，长石阶沿中央轴线向上，尖拱、钟体和瘦高塔身形成强视觉地标。这里既是交易、布道、施粥、教会发布和圣女公开出现的场所，也是群众消息传播、猎羽秩序维护与物资分配的制度性公共节点。钟楼后方可见用户称为“通天塔”的高塔视觉地标，但其交通 / 制度功能不得自动等同关所；合法上层通道继续服从地图中的关所结构。

# 8. 桥北东侧后街窄巷｜EUS-SCN-000004

## 空间与剧情职责

位于高架桥北侧。人物沿主街过桥后继续朝北往钟楼方向行进不久，从右手 / 世界东侧拐入。该后街是第一章尤斯蒂娅被追杀、求救、逃跑的正式街道空间。

## 夜雨视觉描述

天空牢狱下层平民区的雨夜窄巷，是浮空都市遗弃的底层生存缝隙。深夜冷雨持续落下，石板地、粗糙石墙、腐木梁、旧门窗和桶箱全部被雨水浸透，主色是黑、冷蓝灰、脏褐、腐木和铁锈色，只保留少量油灯与门缝暖黄。巷道狭窄弯折，两侧建筑近乎挤合，绳索上挂着湿破衣物与祷文布。右侧内凹处半掩木门前有三级湿滑石阶，门缝暖光像不敢伸出的余火；墙面可见旧告示、羽化病通报和宗教壁龛。积水、排水沟与雨雾把巷尾吞入黑暗。空间母题是“有人逃、有人追、有人看见，却无人敢开门”。

# 9. 教堂钟楼与关所

- 教堂钟楼位于市集广场北端，前方 / 南侧有长石阶；圣女可在塔前或塔基区域布道。
- 关所位于钟楼后方 / 北侧，其底层入口仍属于牢狱底层；教堂钟楼不承担通往中层的交通功能。
- 进入关所内部后才通过封闭检查、厚重石门与长距离四方回旋楼梯上升到中层。

# 11. 正式场景登记与调用语义

- 用户说“桥南边往北看”时，先解析 Scene 和真实 Camera Anchor，再确定 `facing_cardinal=N`。
- 同一场景多个机位都朝北时，必须先由人物位置 / 调度 / 用户指定确定 Camera Anchor。
- 用户说“反打”时必须查询 Relation，不能简单把 N 改 S。
- 中文显示名可以优化，机器 ID 一旦分配保持稳定。
- 二进制媒体默认使用 ASCII storage filename；中文名、用途、方向和机位信息保存在 GitHub metadata。
