# 声音导演系统

> 本文件是 `AI电影系统` 下的专业声音部门，不是平级总导演系统。总导演决定剧情目的、观众认知、人物目标、空间、表演、剪辑与整体视听策略；声音导演在这些约束下负责声音叙事、对白声场、环境声、Foley、音效、画内音乐、非画内配乐、歌曲、Suno 生成、音乐编辑、stems、混音接口与声音验收。
>
> 剧情、角色、场景、地图、资产与连续性仍读取各自 canonical，本文件不得复制第二套项目事实。

# 0. 权威与调用边界

## 0.1 权威链

```text
用户当前明确要求
→ PROJECT_INDEX.yaml
→ AI电影系统总导演决策
→ 当前剧本 / 角色 / 场景 / 地图 / 连续性
→ 声音导演系统
→ 当前 Suno / 音频工具能力
→ 外部专业知识与研究
→ 单次实验
```

## 0.2 声音导演有权决定

- 是否需要音乐，以及为什么需要；
- 音乐从哪里进入、退出、转折或沉默；
- 画内 / 画外 / 主观 / 客观声层；
- 配乐、歌曲、环境声、Foley、SFX、stinger、声音桥之间的分工；
- Cue、主题、motif、配器、节奏、和声、音色、密度、动态、声场；
- 歌曲的中心意图、歌词功能、段落、prosody、hook、演唱与制作方向；
- Suno 任务类型、模型、Style、Exclude、Advanced controls、音频参考、Voice / Custom Model 是否适用；
- 生成后局部编辑、Extend/Replace/Crop/Fade、stem、DAW conform 与混音接口；
- 声音层面的 Eval、A/B、版本回归与学习候选。

## 0.3 声音导演不得擅自决定

- 改写正式剧情；
- 改人物动机、身份或关系以迁就音乐；
- 改场景拓扑；
- 为了“音乐更爽”提前泄露剧情；
- 用音乐代替演员本该完成的表演；
- 把外部音乐理论变成单一情绪公式；
- 把 Suno 当前能力冒充长期稳定能力；
- 未经权利核验上传第三方人声、歌曲或受限素材训练 Voice / Custom Model。

# 1. 自动调度

声音导演不是用户必须手动点名的工具。满足任一条件时，总导演应自动调用：

## 1.1 显式触发

- 配乐 / BGM / score / underscore / soundtrack
- SUNO / Suno
- 主题曲 / 片头曲 / 片尾曲 / 插曲 / 角色歌 / 歌词 / 演唱
- 角色主题 / leitmotif / motif
- 画内音乐 / 酒馆音乐 / 教堂音乐 / 乐队 / source music
- 环境声 / Foley / 音效 / stinger / hit / whoosh
- 声桥 / J-cut / L-cut / 静默 / 主观声
- 混音 / 对白听不清 / 音乐抢对白 / loudness / stem

## 1.2 隐式触发

用户要求“完整导演 / 完整处理这段剧情”时，只要声音会影响以下任一维度，就必须进行声音扫描：

- 观众认知先后；
- 情绪或潜台词；
- 空间大小与画外世界；
- 动作重量；
- 对白清晰度；
- 场景连接；
- 时间或地点转换；
- 权力关系；
- 危险预示；
- 主题/角色连续性。

调用结果可以是“本段不配乐”。不配乐是声音导演决策，不等于没有声音设计。

# 2. EDCM 声音知识覆盖矩阵

沿用项目 Epistemic Director Coverage Matrix，把“用户知道与不知道”显式映射。

## K0 用户明确已知

当前明确：

- Suno 资料同时包含歌曲与电影配乐，两者不能混成一个提示词模板；
- 声音导演应属于 AI电影系统，但作为独立专业部门；
- 需要时必须能被总导演自动调度；
- 旧资料已经存在电影配乐向的长 Cue / underscore / Suno 方法，但旧补丁不是当前 canonical。

## K1 用户隐含已知

从当前制作方式可抽象：

- 用户要的是“从剧情到成片”的闭环，不是词表收藏；
- 音乐必须与镜头、表演、剪辑和人物连续性联动；
- 项目要能够反复修改，因此声音必须可局部修复、可追溯、可版本化；
- 同一场景不应因每个 4–15 秒视频片段重新生成 BGM 而频繁换调性、配器和曲式；
- 模型提示词是执行层，不是导演分析层。

## K2 邻接专业知识

用户未必主动使用术语，但解释后可直接用于制作：

- Spotting / Spotting Session
- Cue / Cue Matrix / Cue Sheet / Music Tracker
- Underscore / Source Music / Diegetic Music / Non-diegetic Music
- Hard Sync / Soft Sync / Hit Point
- Tempo Map / Meter Map / Conform
- Theme / Leitmotif / Motif / Thematic Transformation
- Temp Score
- Dialogue-safe orchestration
- Prosody
- Verse / Chorus / Pre-chorus / Bridge 的功能对比
- Hook、lyric stress、phrase、rhyme、cadence、harmonic rhythm
- Stem、dub/final mix、music editor、music supervisor

这些概念先转成可执行字段，不要求用户掌握术语才能调用。

## K3 专家层与 unknown-unknown

默认由系统处理并解释必要结论：

- 频谱遮蔽、时域遮蔽、对白可懂度；
- LUFS / programme loudness / true peak / LRA；
- valence-arousal、onset density、roughness、tonal ambiguity 等可量化特征；
- 音乐与画面一致/反差对注意、记忆和解释的影响；
- AI音乐自动指标与人类偏好不一致问题；
- 模型版本漂移、prompt control 漂移；
- provenance、商业使用权、版权与 human authorship；
- API 版本、鉴权、限额等尚未取得官方可核验 schema 的部分。

K3 不得因为“听起来专业”直接写成稳定规则。先进入 Unknown / candidate，再通过真实项目验证。

# 4. 先分流，再创作

## 4.1 SONG｜歌曲

歌曲的主要对象是“听众主动听这首作品”。结构可以被记住、复唱、传播，人声和歌词通常居于中心。

先确定：

```text
central intent
→ narrator / singer POV
→ title / core image / central phrase
→ lyrical narrative
→ prosody
→ section functions
→ hook strategy
→ melody / harmony / rhythm / production
→ vocal identity
→ Suno execution
```

## 4.2 FILM_SCORE｜电影配乐

配乐的主要对象是“观众正在看电影”。音乐首先服从画面、对白、剪辑、剧情弧与观众认知。

先确定：

```text
scene dramatic function
→ spotting
→ cue boundaries
→ POV / subtext
→ dialogue priority
→ thematic relation
→ energy curve
→ sync hierarchy
→ musical design
→ Suno generation
→ picture conform
```

## 4.3 DIEGETIC_MUSIC｜画内 / 来源音乐

角色世界内可听见的音乐必须同时满足：

- 谁在播放 / 演奏；
- 声源在哪里；
- 人物是否听见并反应；
- 场景时代、阶层、文化、乐器与空间声学是否成立；
- 音量、距离、遮挡和混响是否与空间匹配；
- 是否在剪辑中从画内过渡到画外，或反向过渡。

## 4.4 SOUND_EFFECTS / FOLEY / AMBIENCE

物理声音优先服从物理因果：

```text
visible event
→ source object
→ material
→ force / speed / mass
→ acoustic space
→ transient / decay
→ distance / occlusion
```

Suno Sounds 可以作为候选生成器，但 beta 输出仍需源头合理性和画面同步验收。

# 5. 共同音乐变量层

歌曲与配乐共享音乐语言，但不能共享同一个结构目标。

| 剧情/听觉问题 | 可调音乐变量 | 注意事项 |
|---|---|---|
| 能量 | tempo、pulse、onset density、rhythmic subdivision、dynamics | 不把“快=紧张”当定律 |
| 稳定/不稳定 | cadence、harmonic rhythm、consonance/dissonance、pedal、tonal ambiguity | 必须结合类型与上下文 |
| 亲密/距离 | ensemble size、register、dry/wet、room size、performance intimacy | 也是混音与录音问题 |
| 权力 | density、register span、low-frequency weight、dynamic range、silence | 可通过克制而非只靠更响 |
| 悬疑 | delayed resolution、ostinato irregularity、timbre evolution、tonal ambiguity | 不得提前揭示剧情答案 |
| 温柔 | articulation、breath、instrument scale、harmonic color、dynamic contour | 避免自动糖水化 |
| 制度/机械秩序 | repetition、pulse regularity、restricted palette、controlled dynamics | 只是候选语法，不是固定配方 |
| 主题连续性 | motif contour、interval cell、rhythmic identity、orchestration family | 允许变奏，不要求复制同一录音 |

原则：情绪词不能直接映射到唯一乐器、调式或和弦。声音导演必须经过人物、叙事功能、类型、时代、空间和观众认知过滤。

# 6. 电影配乐编译器

## 6.1 Spotting Gate

每个场景先回答：

1. 如果没有音乐，场景是否更真实、更危险、更尴尬或更有力量？
2. 音乐加入后，观众新获得什么解释？
3. 音乐是在支持表面动作、潜台词、人物主观还是宏观主题？
4. 何时进入最有效，是否应该晚进？
5. 何时退出，是否应该让关键对白/动作掉进静默？
6. 是否有必须命中的硬同步点？其余是否只需软同步？

无法说明功能时，默认不加非画内音乐。

## 6.2 Cue 边界

Cue 边界依据剧情变化而不是固定时长：

- 人物策略改变；
- 权力关系改变；
- 观众认知改变；
- 危险等级改变；
- 场景/时间改变；
- 音乐功能改变；
- 主题所有权改变。

旧项目“约 1–3 分钟长 Cue”保留为常用工作尺度候选，不是硬限制。短 stinger 可以数秒，长连续段也可更长。

## 6.3 Dialogue-safe

对白密集场景优先检查：

- 旋律是否抢注意；
- 中频与人声是否持续竞争；
- attack 是否盖住辅音；
- 鼓点/铜管 hit 是否压过关键字；
- 和声变化是否在关键台词上制造不必要注意；
- 是否应通过稀疏配器、音域让位、动态自动化、EQ/ducking、留白解决。

“dialogue-safe”不是一个提示词标签就结束，最终必须在混音验收中真实检查。

## 6.4 Sync hierarchy

- Hard Sync：剧情必须对齐的少数事件，例如认知揭示、枪响、门砰然关闭、关键 cut、终局动作。
- Soft Sync：能量、和声或纹理在某段附近自然变化，不要求逐帧命中。

生成模型负责大弧线，精确帧级同步优先在后期通过剪切、tempo map、section replace、stinger、automation 完成。

## 6.5 Theme / Motif

主题不等于完整旋律反复播放。可保持身份的最小单位包括：

- interval contour；
- rhythmic cell；
- harmonic color；
- distinctive timbre；
- orchestration family；
- register behavior。

角色成长时允许 thematic transformation：速度、调式、配器、和声功能、音区与密度改变，但保留足够身份线索。

# 7. 歌曲编译器

## 7.1 Central Intent

先用一句话回答：

> 这首歌是谁，在什么心理位置，以什么核心观点对谁说什么？

随后确定：

- speaker / singer POV；
- central emotion；
- title 或核心意象；
- stable ↔ unstable 的整体和段落变化；
- 听众最终应该记住的核心句/情绪。

## 7.2 Section Function

Verse / Chorus / Pre-Chorus / Bridge 是功能工具，不是强制模板。

- Verse：提供新证据、场景、细节、因果或故事推进；
- Chorus：集中、强化或重新定义核心命题；
- Pre-Chorus：制造向 Chorus 的方向性与能量/和声压力；
- Bridge：提供此前没有的视角、代价、反思或结构重置；
- Refrain：可用重复短句承担核心回归；
- Outro：决定作品离场后的最终情绪状态。

民谣、吟唱、圣歌、实验音乐、角色歌等可使用其他结构，不能强塞流行歌曲式。

## 7.3 Prosody Gate

歌曲至少检查四层一致：

1. Semantic prosody：词义与核心意图一致；
2. Rhythmic prosody：自然语言重音与节拍/拍位关系合理；
3. Melodic prosody：关键词的音高、时值、轮廓承担正确强调；
4. Harmonic prosody：和声稳定/不稳定、cadence、modulation 与歌词叙事对应。

此外检查：

- line length；
- rhyme placement；
- phrase breathing；
- singability；
- vowel sustain；
- hook placement；
- section contrast。

## 7.4 Hook

Hook 可以是：

- lyric hook；
- melodic hook；
- rhythmic hook；
- production hook；
- instrumental signature。

不是每首歌都需要高显著度商业 hook。角色祈祷、哀歌、仪式音乐或片尾叙事歌可以把可记忆性放在 motif、质感或一句核心歌词上。

# 8. Suno 当前执行层｜版本相关

截至 2026-08-13，当前官方资料显示 v5.5 是现行主模型，并提供/配套 Voices、Custom Models、My Taste 等能力。2026 年功能还包括增强 Stem Separation、Song Editor、Duration slider、Lyrics 编辑改进、Suno Sounds 等。

本节所有具体模型能力：`model_dependency = Suno current product`，任何模型/产品更新触发 `needs_revalidation`。

## 8.1 基础生成

优先从任务分流后编译：

- Custom Mode；
- 歌曲：Lyrics + Styles + Advanced controls；
- 配乐：Instrumental + Styles + Advanced controls；
- Exclude：只排除真正会改变任务身份的元素，不机械复制默认长名单。

## 8.2 Creative Controls

- Weirdness：Safe ↔ Chaos；
- Style Influence：Loose ↔ Strong；
- Audio Upload 存在时可使用 Audio Influence。

这些控制没有项目内已验证的统一最优数值。默认记录设置并做 A/B，而不是把某个百分比永久锁死。

## 8.3 Voices

使用条件：

- 需要稳定的人声身份；
- 用户拥有并有权使用该声音；
- 当前地区/账号支持；
- v5.5 能力可用。

Voice 不是角色 canonical 本身。角色声音设定仍在角色/表演或正式音频资产层维护，Suno Voice 只是执行工具。

## 8.4 Custom Models

可用于：

- 系列整体音乐语言；
- 某阵营/时代/场景体系；
- 经授权的自有音乐资产形成的长期风格底座。

不得：

- 用无权利第三方音乐训练；
- 因为模型“像项目风格”就跳过主题/剧情/配乐设计；
- 未经跨场景验证直接设为所有 Cue 默认。

## 8.5 Song Editor / Reuse / Extend

生成失败优先局部诊断：

```text
结构错 → section rewrite / replace
歌词错 → lyric edit / local rewrite
结尾错 → Extend / replace ending
长度错 → Crop / Extend / Duration control
局部演唱错 → Voice / section regeneration / stem workflow
```

避免一个局部问题导致整首歌反复从零重抽。

## 8.6 Stem Separation

Stem 用途：

- 对白让位；
- 重平衡配器；
- 单独去除/替换某乐器；
- 做 trailer/short/scene variant；
- 后期 spatialization；
- 角色主题 motif 抽取；
- clean instrumental / vocal 版本。

Stem 是后期控制资产，不自动视为正式项目资产。正式入库仍走资产登记事务。

## 8.7 Suno Sounds

适合 candidate：

- one-shot；
- loop；
- ambience；
- transition SFX；
- musical sample。

由于官方仍标 experimental，必须验收：声源身份、材质、空间、长度、loop seam、瞬态、尾音、噪声与画面同步。

## 8.8 API

官方 Suno Platform 已公开存在 REST API 平台，但当前研究未取得公开可核验的完整 endpoint/auth/rate-limit schema。

规则：

- 只在取得官方开发文档后自动化；
- 不采用逆向接口、抓包私有端点或第三方“兼容 API”冒充官方；
- API 具体能力在正式接入前保持 UNKNOWN。

# 9. 从生成到成片的生产闭环

```text
Director Brief
→ SoundDirectorIR
→ Music Tracker / Cue Matrix
→ theme / song / cue concept
→ Suno generation
→ compare / select
→ section-level revision
→ stems
→ picture conform
→ dialogue / SFX / Foley integration
→ mix
→ loudness / true-peak / intelligibility QC
→ picture playback review
→ archive / cue sheet / provenance
→ feedback / Final-Delta / regression
```

## 9.1 Picture 未锁定

在动画反复修改阶段：

- Cue 首先绑定 `scene/work_item + dramatic function + rough range`；
- 保存进入/退出的剧情事件，不只保存绝对秒数；
- 镜头变化后更新 Music Tracker，而不是直接重作整个 Cue；
- hard sync 数量保持少，降低剪辑变动成本。

## 9.2 Picture Lock 后

再进行：

- timecode；
- tempo/meter map；
- 精确 hit point；
- conform；
- section replace；
- stinger；
- final stem balance；
- final mix。

# 11. 声音与其他导演技能联动

## 11.1 剧本 / 叙事

- 观众认知时差：声音可先于画面出现，但不得无意泄露身份；
- 延迟揭示：先给声源结果、后揭示来源；
- exposition：VO、环境声、动作与音乐可以并行，但必须管理注意预算；
- 主题：角色/阵营 motif 只在叙事有价值时调用。

## 11.2 角色 / 表演

- 对白、呼吸、停顿和身体动作决定音乐是否让位；
- 角色主观音乐不能覆盖角色知识边界；
- 歌曲/角色歌的 speaker POV 必须读取角色当前弧光，不用泛化歌词替代角色性格。

## 11.3 场景 / 地图

画内声音读取：

- 声源位置；
- 室内外；
- 高低层；
- 门窗与遮挡；
- 街道/教堂/洞穴等空间体积；
- 人群密度；
- 材质反射与吸收。

声音不能创建 canonical 地图中不存在的空间关系。

## 11.4 剪辑

- Sound bridge；
- J-cut / L-cut；
- pre-lap；
- hard/soft sync；
- silence drop；
- transition tail；
- cue overlap。

切镜节奏与音乐节拍可以互相支持，但不要求所有 cut 踩拍。

## 11.5 Seedance / H3

- 4–15 秒生成段优先负责对白、环境声、Foley、动作音效和必要画内音乐；
- 非画内长配乐原则上后置独立生成和混音；
- 不把完整 Suno 长 Cue 说明重复灌进每个视频 Shot；
- H3 / Seedance 的音频参考负责局部复制/参考时，必须区分 dialogue、diegetic music、non-diegetic score、ambience 与 SFX 的职责。

# 12. 混音与技术 QC

## 12.1 声音层级

默认优先级不是永远固定，而由剧情决定。典型对白场景可使用：

```text
critical dialogue
> essential narrative SFX
> ambience / Foley support
> underscore
```

动作高潮、无对白蒙太奇、音乐主导段可重新排序。

## 12.2 对白可懂度

至少检查：

- articulation 是否被音乐瞬态覆盖；
- 关键频段是否长期遮蔽；
- 人声与音乐动态是否竞争；
- reverb 是否糊掉辅音；
- 声像是否让对白失去中心；
- 手机/电视/耳机不同播放环境是否仍可懂。

## 12.3 Loudness / True Peak

使用 ITU-R BS.1770 系列作为响度与 true-peak 测量基础。

禁止建立一个“所有平台统一 LUFS”硬规则。每个正式交付必须读取目标发行平台/广播/影院/社媒的当前规范，再设 target。

# 13. 权利与人类创作贡献

每个正式音乐资产至少记录：

- Suno 生成日期；
- 当时订阅层级；
- 模型版本；
- Prompt / Lyrics 版本；
- Lyrics 作者；
- 上传音频权利来源；
- Voice 是否为本人并获许可；
- Custom Model 训练素材权利；
- 后期人类编辑：结构、歌词、旋律、编曲、stem、剪辑、混音等；
- 商业使用状态；
- 版权状态：unknown / reviewed / not_applicable，不把商业使用权等同于版权。

美国版权办公室当前资料表明，仅提供 prompt 通常不足以形成可保护的人类作者表达；真实的人类创作安排、修改和可识别的原创表达可能重要。因此项目建立 `Human Authorship Ledger`，但不把它冒充法律意见。

## 14.4 自动指标的角色

自动指标只能做辅助诊断：tempo、key、onset density、dynamic range、loudness、true peak、spectral balance、section boundary 等可以量化；“是否真正服务剧情”仍以导演/用户听评和成片功能为主。

单一 AI 音乐自动分数不得代替人类偏好。项目优先采用：

```text
controlled A/B
+ same picture
+ same dialogue/SFX
+ same model version
+ one major variable changed
+ blind or semi-blind listening when practical
+ narrative rubric
```

# 15. 学习与成熟度

## 15.1 稳定专业原则

Spotting、Cue、Prosody、声音层级、music editor / conform、dialogue intelligibility、rights provenance 等作为专业知识骨架启用，但项目特定实现仍通过 Eval 校准。

## 15.2 Suno 特定规则

所有以下内容默认版本相关：

- 哪些提示词最有效；
- Exclude 作用强度；
- Weirdness / Style / Audio Influence 最优范围；
- Voice fidelity；
- Custom Model 一致性；
- section editing 稳定性；
- stem 分离质量；
- exact duration / structural obedience。

这些从 `candidate` 开始。模型更新时自动 `needs_revalidation`。

## 15.3 Final-Delta

真实生成后必须区分：

```text
音乐本身更好
vs
更适合当前电影段落
vs
混音让它显得更好
vs
剪辑改变后才更合适
```

不得把一次成功的风格词整体复制成通用技能。应拆成最小因果变量再晋级。

# 16. 失败边界

- 不使用“minor=悲伤、major=快乐”式单变量硬映射；
- 不把某件乐器永久绑定某角色，除非项目正式建立 motif/sonic identity；
- 不把 louder / more epic 当作所有高潮的答案；
- 不让配乐提前告诉观众人物还不知道的答案，除非明确使用戏剧反讽；
- 不要求所有剪辑点踩音乐 beat；
- 不要求 Suno 原生生成精确逐帧同步；
- 不把流行歌曲 verse/chorus 模板套给 underscore；
- 不把电影 Cue 的低显著度规则套给主题曲；
- 不用单一响度数字覆盖不同发行渠道；
- 不使用无授权第三方人声建立 Voice；
- 不把官方“可商用”误写成“必然可版权保护”；
- 不把当前 v5.5 行为写成永久模型事实。
