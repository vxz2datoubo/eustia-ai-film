# 本地问题模式集合

> 本集合记录可复现的本地执行、脚本、编码、解析和 Git 传输问题及其已验证修复。它是学习证据与任务防错清单，不复制导演、资产或剧情规则。稳定规则仍按反馈引擎写回唯一目标主档。

## 1. 使用合同

1. 发布任务前，任务发布者按任务涉及的工具、文件格式和运行环境读取相关模式，并把必要前置检查写入任务验收。
2. 执行中发生失败、修复或环境绕行时，执行者在任务收尾前把可复现模式写入本集合；一次偶发、无根因或含敏感数据的事件只记录到 Unknown Registry 或不记录。
3. 每条必须区分症状、根因、已验证修复、复发检查、适用边界和证据。禁止把未经验证的猜测写成默认操作。
4. 同一问题有多条证据时累积 frequency；达到 project_verified 前只作 conditional recall。任务发布者不得把本集合替代实际测试。

## 2. 条目 schema

issue_id:

## 3. 已验证模式

### LIP-YAML-001｜YAML 列表缩进漂移

```yaml
issue_id: LIP-YAML-001
category: yaml_syntax
frequency: 1
status: project_verified
symptom: mapping 键下的前两项列表缩进正确，后续列表项退到父层级，导致标准 YAML parser 报错。
root_cause: 手工编辑时 sequence item 的缩进与所属 mapping key 不一致；文本 grep 无法验证语法树。
applicable_context: AI_HANDOFF.yaml 和任何由人工维护的 YAML。
safe_fix: 使同一列表的所有 '-' 与所属 key 保持一致层级，并用 PyYAML safe_load 实际解析目标文件。
verification: python -c "import yaml; yaml.safe_load(open(path, encoding='utf-8'))" 成功，且读取预期嵌套字段。
task_release_check: 涉及 YAML 修改时，把 parser validation 列入验收；不得仅以 grep 或 diff 代替。
evidence: PR-1 GPT 第二轮复审发现 AI_HANDOFF.yaml required_before_re_review 的第三项缩进错误；2026-08-12 已由 PyYAML 修复并验证。
non_goals: 不把 YAML parser 成功视为业务字段语义正确；关键字段仍须断言。
```

### LIP-PSPY-001｜PowerShell 调用 Python `-c` 的引号转义

```yaml
issue_id: LIP-PSPY-001
category: shell_quoting
frequency: 1
status: project_verified
symptom: PowerShell 传给 python -c 的嵌套双引号被拆分，Python 出现 SyntaxError，继而造成验证脚本误报失败。
root_cause: PowerShell 字符串和 Python -c 源码同时使用未转义的双引号。
applicable_context: Windows PowerShell 5/7 调用 Python 单行验证脚本。
safe_fix: 外层使用 PowerShell 双引号，Python 字符串使用单引号；先单独运行命令，再嵌入验收脚本。
verification: Python 命令成功执行目标断言；调用方检查 $LASTEXITCODE 并仅在非零时失败。
task_release_check: 任务包含跨 shell 语言内联代码时，验收要求先做最小可运行命令测试并保留退出码检查。
evidence: 2026-08-12 validate_canonical_cutover.ps1 的初版 YAML 调用因 quoting 触发 SyntaxError；调整后实际 PyYAML parse 通过。
non_goals: 不以此规避复杂脚本；多行或复杂逻辑应优先使用受版本控制的脚本文件。
```

### LIP-GIT-001｜Git HTTPS 瞬时连接重置

```yaml
issue_id: LIP-GIT-001
category: git_transport
frequency: 2
status: candidate
symptom: git fetch 或 push 对 github.com 报 Recv failure: Connection was reset，而 gh API 或后续 Git 命令可成功。
root_cause: 尚未确认；当前证据指向瞬时网络/TCP 可达性波动，而非仓库配置或鉴权错误。
applicable_context: Windows 环境经 HTTPS 访问 GitHub。
safe_fix: 保留现有未提交工作，先用 git ls-remote 和 gh API 区分远端状态；以最小范围 git fetch/push 重试。成功前不得声称 main 已同步或远端已更新。
verification: Git fetch/push 返回零，并用远端 ref 或 GitHub API 复核 SHA 与 ahead/behind。
task_release_check: 网络错误发生时记录命令、时间和远端 SHA；禁止用 API 改写 Git 历史替代正常同步，除非获得明确授权。
evidence: PR-1 修复期间 Git fetch 曾 connection reset，后续 fetch/push 成功并由远端 SHA 复核。
non_goals: 不把短暂重试当作永久网络配置修复；连续失败须升级为环境阻塞。
```
