# 视觉资产登记库

> 本文件是角色、场景、服装、白模、深度图、视频参考等**逻辑媒体资产身份、状态、职责、默认指针与连续性绑定**的唯一可写文字登记库。媒体本体继续保存在 ChatGPT Library / Project 可访问位置。
> 正式场景媒体的 Scene / Camera Anchor / View / Media Asset / Media Version / Relation 身份结构统一服从 `../10_运行时/scene_asset_identity_schema.yaml`；场景 Asset 的 current Media Version、版本历史、content hash 与 locator 由 `../10_运行时/scene_media_resolver_manifest.yaml` 唯一维护。本文件不复制第二套版本清单。

## 1. 强制入库语义

用户说“登记资产 / 登记进资产 / 加入资产库 / 录入资产 / 设为正式资产”，默认就是正式 `active` 入库请求，除非用户明确说 `candidate / temporary / pending_review`。

正式完成必须执行：

```text
识别资产身份与职责
→ 检查同类资产 / 默认指针 / 连续性
→ 场景资产解析 Scene → Camera Anchor → View → Media Asset → Media Version → Relation
→ 写本登记库中的逻辑Asset / 默认职责
→ 写resolver manifest中的current version / hash / locator
→ 必要时同步地图 / 场景 / 连续性
→ COMMIT serially
→ FETCH VERIFY
```

Memory、口头确认或“准备好条目”都不能替代正式入库。

## 2. 状态

- `active`：正式逻辑资产；在自己的职责通道中可默认调用。
- `alternate`：合法备选。
- `pending_review`：历史存在但未重新核验，不得默认调用。
- `missing`：登记存在但媒体缺失。
- `active_text_missing_visual`：文字空间节点正式，但独立视觉母图缺失。
- `temporary`：只服务当前镜头，不进入长期身份默认。
- `deprecated`：禁止默认调用。

场景媒体实际像素版本的生命周期由 `scene_media_resolver_manifest.yaml` 的 `pending_verification / current / superseded / archived / missing_binary / rejected` 管理。

## 3. 调用优先级

```text
用户本次明确指定
→ 当前镜头连续性绑定
→ 当前 View 的正式默认 Media Asset
→ resolver manifest 中该 Asset 的 current Media Version
→ 当前版本的 verified locator
→ 合法备选 / 光照时间变体
→ 明确报告缺失
```

## 3.1 正式场景资产身份与命名规则

- 世界绝对方向：**北 = 教堂钟楼 / 关所侧；南 = 绯灯街 / 蔷薇酒馆侧**。
- 用户层和正式显示名统一中文；机器层使用 ASCII opaque ID：`EUS-SCN / EUS-CAM / EUS-VIEW / EUS-AST / EUS-VER / EUS-REL`。
- opaque ID 不编码地点、方向、左右、正反打等可变化语义；中文名变化不改变机器身份。
- Camera Anchor 中文名优先使用**语义机位名**，直接说明摄影机实际站在哪里，例如“前厅入口内侧机位”“广场南侧中央机位”。不默认使用“机位01/02”；只有同一语义位置仍需消歧时才追加数字后缀。
- 普通 View 正式方向只使用：**朝北 / 朝南 / 朝东 / 朝西**，描述摄影机水平朝向。
- 顶视 View 使用：**北朝上 / 南朝上 / 东朝上 / 西朝上**，描述画面顶部世界方位。
- “正打 / 反打 / 左视 / 右视”不作为正式主方向名；同机位180°、90°、跨机位互看与剪辑正反打都通过 Relation 显式绑定。
- 场景母图反复修改时保留 Asset ID，像素修订进入 Media Version；不靠删除旧图或同名覆盖维持身份。

## 3.2 中文正式名格式

```text
Scene：{场景名}
Camera Anchor：{场景名}·{语义机位名}
Perspective View：{camera_anchor_display_name}·朝{北|南|东|西}{视图职责}
Top View：{场景名}·{北|南|东|西}朝上{顶视职责}
Media Asset：{view_display_name}·{媒体角色/时间/天气/光照职责}
Media Version：{media_asset_display_name}·修订{NN}
```

## 3.3 Relation 绑定

- `same_anchor_180`：同一 Camera Anchor 原地180°转向。
- `same_anchor_90`：同一 Camera Anchor 的侧向视图。
- `reciprocal_cross_anchor`：两个不同 Camera Anchor 的互看 / 对位。
- `editorial_shot_reverse_shot`：导演 / 剪辑层明确的正反打关系。
- `top_view_orientation_pair`：同一地点不同朝上方位的顶视配对。
- `continuity_match`：同一连续空间不同机位或层级的连续性绑定。

一个朝北、一个朝南**不自动等于正反打**；必须查询 Relation。

## 3.4 Asset / Media Version / Locator 分层

- `asset_id`：稳定逻辑媒体职责槽。
- `version_id`：某一次实际像素内容的不可变身份。
- File ID、Library title、current conversation path、local path 等只是 locator。
- 同像素重传只补 locator；同职责像素修改新增 Version；时间/天气/光照长期并列版本建立独立 Asset；新机位或新 View 建立新身份。
- 普通替换不物理删除旧版本，旧版默认 `superseded`。
