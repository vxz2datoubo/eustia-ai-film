# 优秀提示词案例学习证据索引

> 本文件只保存 Golden Prompt / Golden Media Case Learning 的外部证据、术语映射、适用边界与再验证条件。操作规则见 `08_系统学习/优秀提示词案例学习协议.md` 与 `10_运行时/golden_media_evidence_schema.yaml`，不得在此建立第二份学习规则。

# 1. OpenAI contextual evals / golden set

- 来源：OpenAI，`How evals drive the next chapter in AI for businesses`，2025-11-19。
- 等级：E1/E2，官方方法论。
- 核心主张：evals 采用 `Specify → Measure → Improve`；领域专家应明确“great”是什么，并建立由真实输入到期望输出的 golden set；真实 inputs / outputs / outcomes 与专家 review 应形成持续 data flywheel。
- 项目转译：用户明确判定优秀案例是 Golden Case 的权威触发，但案例登记与技能晋级必须分离。
- 边界：OpenAI 文档讨论通用 AI workflow，不是 Seedance 专用提示规范。
- 核验地址：https://openai.com/index/evals-drive-next-chapter-of-ai/

# 2. OpenAI 内部 Data Agent 的 Golden Answer + Unit Test

- 来源：OpenAI，`Inside OpenAI’s in-house data agent`。
- 等级：E2，官方真实工程案例。
- 核心主张：golden reference 与 grader 可像持续运行的 unit tests 一样发现 regression。
- 项目转译：优秀案例既是 precedent，也可成为回归参考；开放式电影生成不能机械 exact-match，应按剧情功能、身份、空间、动作、声音、连续性等维度评价。
- 核验地址：https://openai.com/index/inside-our-in-house-data-agent/

# 3. OpenAI Evals / Graders API

- 来源：OpenAI API Reference，Evals / Graders。
- 等级：E1。
- 核心主张：data source schema 与 testing criteria 可分离；grader 可组合多种评分方式，并支持多模态输入。
- 项目转译：Golden Case 不只存 prompt string，还应存可评价 schema；自动 grader 只做诊断，不能覆盖用户导演审美判断。
- 核验地址：
  - https://platform.openai.com/docs/api-reference/evals
  - https://platform.openai.com/docs/api-reference/graders

# 4. OpenAI model snapshot / version drift

- 来源：OpenAI API Reference，Backward compatibility。
- 等级：E1。
- 核心主张：不同模型 snapshot 的 prompting behavior 可能变化；应 pin model version 并建立 evals。
- 项目转译：Golden Case 尽量记录 model/version；大版本变化或行为漂移时 version-bound lesson 进入 `needs_revalidation`。
- 核验地址：https://platform.openai.com/docs/api-reference/backward-compatibility

# 5. Case-Based Reasoning（CBR）

- 来源：Aamodt & Plaza, `Case-Based Reasoning: Foundational Issues, Methodological Variations, and System Approaches`, AI Communications 7(1), 1994。
- 等级：E3，经典同行评议研究。
- 核心主张：历史案例通过 Retrieve → Reuse → Revise → Retain 参与后续推理。
- 项目转译：Golden Case 是可检索、适配、测试、再保留的经验库，不是提示词收藏夹。
- DOI：https://doi.org/10.3233/AIC-1994-7104

# 6. DSPy：示例、程序、指标分离

- 来源：Khattab et al., `DSPy: Compiling Declarative Language Model Calls into Self-Improving Pipelines`, arXiv:2310.03714。
- 等级：E3。
- 核心主张：不把人工长 prompt string 当作唯一知识载体，而把 demonstrations、程序结构与 metric 分离优化。
- 项目转译：案例、可迁移机制、评价指标分别承担不同职责，不机械复制整段优秀提示词为技能。
- 核验地址：https://arxiv.org/abs/2310.03714

# 7. Reflexion：自然语言反馈 + episodic memory

- 来源：Shinn et al., `Reflexion: Language Agents with Verbal Reinforcement Learning`, NeurIPS 2023。
- 等级：E3。
- 核心主张：agent 可在不更新基础模型权重的情况下，把反馈转成 episodic memory 改善后续 trial。
- 项目转译：用户对优秀/失败结果的自然语言评价可进入 GitHub-first 外部长期经验层。
- 边界：这是架构启发，不等于 Seedance 内部机制。
- 核验地址：https://arxiv.org/abs/2303.11366

# 8. Continual Learning / Experience Replay

- 来源：Rolnick et al., `Experience Replay for Continual Learning`, arXiv:1811.11682；Mahdaviyeh et al., `Replay can provably increase forgetting`, CoLLAs 2026。
- 等级：E3。
- 核心主张：历史经验回放可减轻遗忘，但 replay 的收益依赖样本关系，并非越多越好。
- 项目转译：案例库扩大后必须稀疏、相关、多样地召回，并监控 negative transfer，禁止全量注入。
- 核验地址：
  - https://arxiv.org/abs/1811.11682
  - https://proceedings.mlr.press/v330/mahdaviyeh26a.html

# 9. Eval contamination / holdout reuse

- 来源：OpenAI 2026 evaluation contamination 系列；Feldman et al. ICML 2019；Feng et al. UAI 2022。
- 等级：E1/E3。
- 核心主张：持续根据同一测试集调系统会造成 adaptive dependence；已经作为 few-shot/retrieval 输入的 exact case 不能再独立证明泛化。
- 项目转译：高价值案例要产生 sibling transfer / contrast / holdout，而不是用“自己教过的题”证明自己会迁移。
- 核验地址：
  - https://openai.com/index/trustworthy-third-party-evaluations-foundations/
  - https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/
  - https://openai.com/index/separating-signal-from-noise-coding-evaluations/
  - https://proceedings.mlr.press/v97/feldman19a.html
  - https://proceedings.mlr.press/v180/feng22a.html

# 10. LLM-as-a-Judge reference / calibration 风险

- 来源：Kranti & Vajjala, `LLM Judges Can Be Too Generous When There Is No Reference Answer`, arXiv:2607.12885, 2026。
- 等级：E3-preprint / candidate。
- 项目转译：自动 grader 只作为辅助诊断；用户真实评价、真实生成和 reference-aware calibration 权重更高。
- 边界：语言评估研究不能直接量化迁移到视频审美。

# 11. Golden Case 基础结论

当前可高置信采用：

1. Golden Case 由用户/领域专家明确判断触发；
2. Case Memory 与 Skill Memory 分离；
3. source prompt、上下文、模型版本、结果证据与 provenance 保留；
4. exact demonstration 不能独立证明泛化；
5. 自动 grader 不取代用户领域判断；
6. 模型版本变化触发 revalidation；
7. 案例回放必须相关、稀疏、多样；
8. 单个优秀案例不能自动生成 general_stable 规则。

# 12. Seedance 2.0 官方多模态视频参考能力

- 来源：ByteDance Seed，`Seedance 2.0 Official Launch` / 官方模型页，2026-02-12。
- 等级：E1。
- 核心主张：Seedance 2.0 支持 text / image / audio / video 混合输入，可参考构图、动作、镜头语言、动作节奏、视觉特效和声音。
- 项目转译：原视频在“直接作为生成 reference”时具有生产价值；但 Golden Case 长期学习并不因此必须永久保存所有原视频。若用户选择 GitHub 时间证据包为默认持久化，原视频可只在摄取阶段存在；只有不可压缩的动作/声音证据或明确 reference 生产需求时例外保留。
- 边界：2.0 官方能力不能静默等同 C-DANCE 2.5 的内部训练配方或行为。
- 核验地址：
  - https://seed.bytedance.com/blog/seedance-2-0-official-launch
  - https://seed.bytedance.com/zh/seedance2_0

# 13. VBench / VBench-2.0：视频评价必须拆维度

## 13.1 VBench

- 来源：Huang et al., `VBench: Comprehensive Benchmark Suite for Video Generative Models`, CVPR 2024。
- 等级：E3，顶会同行评议。
- 核心主张：视频质量应拆成 subject consistency、background consistency、temporal flickering、motion smoothness、dynamic degree、aesthetic quality、imaging quality、spatial relationship 等细粒度维度，并用人类偏好验证对齐程度。
- 项目转译：“电影感/高级感”不能掩盖身份、动作、空间、时序稳定等独立失败。
- 核验地址：https://openaccess.thecvf.com/content/CVPR2024/html/Huang_VBench_Comprehensive_Benchmark_Suite_for_Video_Generative_Models_CVPR_2024_paper.html

## 13.2 VBench-2.0

- 来源：`VBench-2.0: Advancing Video Generation Benchmark Suite for Intrinsic Faithfulness`, arXiv:2503.21755。
- 等级：E3-preprint / candidate。
- 项目转译：Human Fidelity、Controllability、Creativity、Physics、Commonsense 可作为更深层验收候选维度。

# 14. T2V-CompBench：Prompt→Video 绑定要拆成组合控制

- 来源：Sun et al., `T2V-CompBench`, CVPR 2025。
- 等级：E3。
- 核心主张：consistent/dynamic attribute binding、spatial relationship、motion binding、action binding、object interaction、numeracy 等需要独立评价。
- 项目转译：Prompt clause 必须对齐具体秒级 evidence range 与可观察控制维度，不能只做整段文本与整段视频相似度。
- 核验地址：https://openaccess.thecvf.com/content/CVPR2025/html/Sun_T2V-CompBench_A_Comprehensive_Benchmark_for_Compositional_Text-to-video_Generation_CVPR_2025_paper.html

# 15. VideoScore / EvalCrafter：自动评价应模拟多维人类反馈

- 来源：`VideoScore: Building Automatic Metrics to Simulate Fine-grained Human Feedback for Video Generation`, arXiv:2406.15252；Liu et al., `EvalCrafter`, CVPR 2024。
- 等级：E3。
- 核心主张：视频评价应多维、对齐人类意见，而非单一总分。
- 项目转译：自动 grader 适合大规模筛查与定位问题；必须项目内校准与用户 verdict 的相关性。
- 核验地址：
  - https://arxiv.org/abs/2406.15252
  - https://openaccess.thecvf.com/content/CVPR2024/html/Liu_EvalCrafter_Benchmarking_and_Evaluating_Large_Video_Generation_Models_CVPR_2024_paper.html

# 16. 多粒度视频检索：InternVideo2 / VideoPrism / VideoRAG

- 来源：InternVideo2；Google VideoPrism；VideoRAG。
- 等级：E3 / E2-E3。
- 核心主张：高质量 video-text pairs、机器/噪声文本、视频自身动态表征、shot/clip 级表示与文本检索是互补信号；单一封面图不足以代表视频动态。
- 项目转译：未来大规模 Golden Case 检索可组合 retrieval card / timeline segment / contact sheet embedding，但当前稳定入口必须是可审计的文字检索卡和 timeline。
- 核验地址：
  - https://arxiv.org/abs/2403.15377
  - https://research.google/blog/videoprism-a-foundational-visual-encoder-for-video-understanding/
  - https://arxiv.org/abs/2502.01549

# 17. ByteDance Seedance 1.0：官方公开训练管线与本项目方案高度同构

- 来源：ByteDance Seed，`Tech Report of Seedance 1.0 Is Now Publicly Available`，2025-06-11。
- 等级：E1，官方技术博客 / 技术报告。
- 官方公开要点：
  1. 大规模、多来源视频数据覆盖时长、分辨率、主体、场景、风格、运镜等维度；
  2. 通过 inter-frame visual dissimilarities 做自动 shot boundary detection，把长视频精确切成短片段；
  3. 训练 precise caption model 为视频生成训练 caption；
  4. dense caption 明确融合 dynamic 与 static 两路信息：dynamic 细致描述动作和运镜变化，static 描述关键帧中的核心人物或场景；
  5. 多镜头训练按动作时间顺序组织 shot，并让每个 shot 携带详细 caption；
  6. SFT 使用精选高质量 video-text pairs 与精准 caption；
  7. 后训练采用基础、运动、美学三类 reward model，并进行 video-tailored RLHF；
  8. aesthetic reward model 采用视频 keyframes 作为 image-space 输入。
- 项目转译：用户提出的“视频 → shot/序列证据 → 动静态文字描述 → 提示与效果学习 → 评价反馈”不是臆想，而与前沿生成模型公开数据/后训练管线高度相似。项目差异是我们不更新 Seedance 权重，而通过 GitHub 外部经验库、检索、Prompt 编译、A/B 与 regression 实现 continual learning。
- 边界：官方资料没有证明 Seedance 1.0/2.0/2.5 会把每条视频逆向恢复成其历史真实原 Prompt，也没有证明 dense caption 本身能学习真正物理因果。
- 核验地址：https://seed.bytedance.com/en/blog/tech-report-of-seedance-1-0-is-now-publicly-available

# 18. Seedance 1.5 pro：音频描述进入训练数据链

- 来源：ByteDance Seed，`Seedance 1.5 pro: A Native Audio-Visual Joint Generation Foundation Model` / 官方发布博客，2025-12。
- 等级：E1。
- 核心主张：统一音视频联合生成；multi-stage data pipeline 强调 audio-video coherence、motion expressiveness、curriculum scheduling，并“增强视频 caption 的专业性、融合 audio descriptions”；随后用高质量 AV 数据做 SFT 与音视频场景 RLHF，多维奖励改善运动、美学、音频保真。
- 项目转译：Golden Case 的声音层不能只保存台词 ASR，应把说话方式、韵律、BGM、SFX、ambience、onset/beat 与 visual event 对齐到同一秒级 timeline。
- 边界：文字化声音会损失真实音色、频谱、混响与微妙混音；声音本身是 Golden 属性时需要例外保存紧凑声学证据。
- 核验地址：https://seed.bytedance.com/en/blog/sound-and-vision-all-in-one-take-the-official-release-of-seedance-1-5-pro

# 19. Seedance 2.0：物理改善的公开归因不是“只靠 caption”

- 来源：ByteDance Seed，Seedance 2.0 官方发布，2026-02-12。
- 等级：E1。
- 核心主张：官方将 2.0 的物理规律遵循、长效一致性与“海量世界知识、稀疏架构效能、多模态联合训练产生的泛化能力”联系起来，并继续强调与人类反馈深度对齐。
- 项目转译：用户观察到 Seedance 2.0 的复杂动作/物理效果强是合理观察；但不能把原因单独归结为“视频反推 Prompt”。更合理的机制组合是：数据规模与分布 + 精准 caption + 时空架构 + multimodal joint training + 高质量 SFT + motion/structure/aesthetic/audio rewards + RLHF + 世界知识。
- 边界：截至本次研究，公开资料不足以还原 C-DANCE 2.5 的专有数据清洗、caption、reward 与 post-training 配方。
- 核验地址：https://seed.bytedance.com/blog/seedance-2-0-official-launch

# 20. ByteDance Seed1.5-VL / 豆包视频理解：动态帧率 + 时间定位 + 向量检索

- 来源：ByteDance Seed，Seed1.5-VL 官方技术报告/博客，2025-05。
- 等级：E1。
- 核心主张：支持 dynamic frame-rate sampling，显著增强视频 temporal localization；结合 vector search 可定位与文本描述对应的视频片段。
- 项目转译：用户提到豆包“问几秒发生什么”的体验有公开技术方向支持。Golden Case 应支持 `time → description` 与 `description → time` 双向查询；固定抽帧不应是唯一策略。
- 核验地址：
  - https://seed.bytedance.com/blog/first-release-of-seed-vlm-tech-report-comprehensive-solutions-for-image-video-gui-and-game
  - https://seed.bytedance.com/en/public_papers/seed1-5-vl-technical-report

# 21. Qwen2.5-VL：动态 FPS + 绝对时间编码支持秒级事件定位

- 来源：Qwen 官方博客，Qwen2.5-VL。
- 等级：E1，官方技术资料。
- 核心主张：dynamic FPS training + absolute time encoding，让时间位置与真实时间流速对齐，可实现 hour-scale understanding 与 second-level event localization。
- 项目转译：本项目所有用户可见时间定位以秒数为主，frame index 仅保留为技术辅助；这符合现代 Video-VLM 对“时间语义”而非“帧编号”的建模方向。
- 核验地址：https://qwenlm.github.io/blog/qwen2.5-vl/

# 22. Google Vid2Seq：时间 token + ASR 可把事件描述与时间边界统一成一条序列

- 来源：Google Research，Vid2Seq，CVPR 2023。
- 等级：E2/E3，官方研究博客 + 顶会论文。
- 核心主张：dense video captioning 同时做 temporal localization 与 event description；特殊 time tokens 表示离散时间戳；visual encoder 与 text encoder 同时处理 frames 和 transcribed speech，并用 speech sentences + timestamp 做监督。
- 项目转译：`timeline.yaml` 应把视觉、对白和声音事件原生对齐到 start_s/end_s，而不是分别写成互不关联的摘要。
- 核验地址：https://research.google/blog/vid2seq-a-pretrained-visual-language-model-for-describing-multi-event-videos/

# 23. Google Neptune：frame captions + ASR + shot-level summarize 是可扩展企业管线先例

- 来源：Google Research，Neptune，2024。
- 等级：E2/E3。
- 核心主张：长视频处理先提取 ASR captions 与约 1fps frame captions，再把视频切 shot、按 topic 聚合，并由 LLM 将 ASR + frame captions 汇总为 shot-level captions，最后做人审校验。
- 项目转译：本项目可采用“自动证据提取 → shot/segment 汇总 → 人/导演 verdict”三层流水线；固定采样只是输入之一，不是最终长期存储要求。
- 核验地址：https://research.google/blog/neptune-the-long-orbit-to-benchmarking-long-video-understanding/

# 24. Meta PLM-Video：时间→描述与描述→时间的双向监督

- 来源：Meta AI Research，PLM Data，2025。
- 等级：E1/E3，官方研究数据发布。
- 核心主张：Region Video Captioning (RCap) 给定时间区间生成详细事件描述；Region Temporal Localization (RTLoc) 反向给定文本描述预测开始/结束时间；Region Dense Temporal Captioning (RDCap) 用 `(start, end, caption)` 序列覆盖主体整段事件轨迹。
- 项目转译：Golden Case timeline 同时提供 forward captioning、reverse localization、dense subject timeline，正好对应用户“几秒发生什么 / 某动作发生在几秒”的双向需求。
- 核验地址：https://ai.meta.com/datasets/plm-data/

# 25. VITED：固定均匀抽帧会漏掉非均匀关键证据

- 来源：Lu et al., `VITED: Video Temporal Evidence Distillation`, CVPR 2025。
- 等级：E3，顶会同行评议。
- 核心主张：统一固定数量的均匀帧可能漏掉分散且非均匀出现的关键证据；ViTED 学习 temporal evidence windows 与 chain-of-evidence。
- 项目转译：0.5s sampling 只保留为 safety baseline；长期持久化必须使用 shot boundary、动作阶段、接触、构图变化、音频 onset、用户关注点等自适应证据，并执行 perceptual dedup。
- 核验地址：https://openaccess.thecvf.com/content/CVPR2025/html/Lu_VITED_Video_Temporal_Evidence_Distillation_CVPR_2025_paper.html

# 26. OpenAI Sora：Recaptioning 证明“视频→高描述文本→生成训练”是通用强路线

- 来源：OpenAI，`Video generation models as world simulators` / Sora System Card。
- 等级：E1，官方技术说明。
- 核心主张：训练高度描述性的 captioner，为视觉训练数据生成 detailed captions；训练在这些 captions 上改善 text fidelity 与整体视频质量；推理时也把短用户 prompt 扩展成更长的 detailed caption 再送入视频模型。
- 项目转译：只有视频时生成 `reconstructed_prompt` 与详细 screen description 是合理的学习路线，但它是“重建一个可复现描述”，不是恢复历史真实原 Prompt。
- 核验地址：
  - https://openai.com/index/video-generation-models-as-world-simulators/
  - https://openai.com/index/sora-system-card/

# 27. Prompt 优化：RAPO / Prompt-A-Video / VPO

- 来源：Gao et al., RAPO, CVPR 2025；Ji et al., Prompt-A-Video, ICCV 2025；Cheng et al., VPO, ICCV 2025。
- 等级：E3，顶会同行评议。
- 核心主张：
  - RAPO 用 retrieval-augmented prompt optimization，从 learned relational graph 检索 modifier，并用 LLM 重写，提升静态和动态生成维度；
  - Prompt-A-Video 通过 reward-guided prompt evolution 形成 optimal prompt pool，再 SFT + 多维 reward + DPO，使 Prompt 适配特定视频模型偏好；
  - VPO 进一步把 text-level 与 video-level feedback 纳入 prompt preference learning。
- 项目转译：Golden Case 的真正生产价值不是“存下来”，而是：模糊需求 → 检索高相关 precedent → 只迁移匹配机制 → 编译当前模型 Prompt → 真实生成 → video-level feedback → Final-Delta → 更新案例边界。
- 核验地址：
  - https://openaccess.thecvf.com/content/CVPR2025/html/Gao_The_Devil_is_in_the_Prompts_Retrieval-Augmented_Prompt_Optimization_for_CVPR_2025_paper.html
  - https://openaccess.thecvf.com/content/ICCV2025/html/Ji_Prompt-A-Video_Prompt_Your_Video_Diffusion_Model_via_Preference-Aligned_LLM_ICCV_2025_paper.html
  - https://openaccess.thecvf.com/content/ICCV2025/html/Cheng_VPO_Aligning_Text-to-Video_Generation_Models_with_Prompt_Optimization_ICCV_2025_paper.html

# 28. 因果边界：视频先后顺序 ≠ 真因果

## 28.1 ByteDance / ICML 2025：Scale 不会自动发现物理定律

- 来源：Kang et al., `How Far Is Video Generation from World Model: A Physical Law Perspective`, ICML 2025；ByteDance Seed 官方研究介绍。
- 等级：E3 + E2。
- 核心主张：视频生成模型在分布内可表现很好，但 OOD 物理泛化失败；实验显示模型更像 case-based generalization，模仿最相近训练样本，而不是稳定抽象出一般物理法则。
- 项目转译：大量优秀案例可以显著提高先例覆盖与模仿/迁移能力，但案例数量本身不能证明系统形成真正物理定律；必须设计 counterfactual、OOD、边界和 controlled intervention。
- 核验地址：
  - https://proceedings.mlr.press/v267/kang25g.html
  - https://seed.bytedance.com/en/blog/can-a-video-generation-model-understand-the-laws-of-physics-doubao-seed-team-announces

## 28.2 CaST-Bench：因果推理要绑定多段时空证据

- 来源：Zhang et al., `CaST-Bench`, CVPR 2026。
- 等级：E3。
- 核心主张：复杂因果问题需要定位 causal chain 中多个 spatio-temporal evidence；当前 VLM 在精确 grounded causal chain 上仍困难，grounding 有助减少 spurious correlation。
- 项目转译：每条因果边必须保存 evidence_time_ranges、可见接触/状态变化、替代解释、反事实问题和置信度。
- 核验地址：https://openaccess.thecvf.com/content/CVPR2026/html/Zhang_CaST-Bench_Benchmarking_Causal_Chain-Grounded_Spatio-Temporal_Reasoning_for_Video_Question_Answering_CVPR_2026_paper.html

## 28.3 MASS：物理理解需要运动、空间、3D 与 tracking 信号

- 来源：Wu et al., `MASS: Motion-Aware Spatial-temporal Grounding for Physics Reasoning and Comprehension in VLMs`, CVPR Findings 2026。
- 等级：E3。
- 核心主张：仅标准视频语义不足以解决物理推理；显式 depth-based 3D encoding、visual grounding、motion tracking 可提升物理理解。
- 项目转译：对于接触、重心、轨迹、前后状态等高价值案例，timeline 可扩展 `contact_and_support / state_change / spatial_relationship / motion_trace`，而不是只写“动作很自然”。
- 核验地址：https://openaccess.thecvf.com/content/CVPR2026F/html/Wu_MASS_Motion-Aware_Spatial-temporal_Grounding_for_Physics_Reasoning_and_Comprehension_in_CVPRF_2026_paper.html

# 29. Self-Evolving Visual Concept Library：案例库可通过 critic 迭代概念

- 来源：Sehgal et al., `Self-Evolving Visual Concept Library using Vision-Language Critics`, CVPR 2025。
- 等级：E3。
- 核心主张：VLM critic 可以结合概念历史表现迭代改进视觉 concept library，并考虑概念之间的交互。
- 项目转译：Golden Case 越积越多后，不应该无限增加同义标签；系统应根据真实检索/迁移成功与失败，合并、细化或限定视觉/导演概念。新概念仍需 provenance、边界与 maturity，不能由 critic 自说自话升级成项目事实。
- 核验地址：https://openaccess.thecvf.com/content/CVPR2025/html/Sehgal_Self-Evolving_Visual_Concept_Library_using_Vision-Language_Critics_CVPR_2025_paper.html

# 30. 2026-08-15 企业级媒体 Golden Case 综合结论

当前可高置信采用：

1. **摄取时看完整视频，长期默认不保存原视频。** 将其蒸馏为 GitHub `case bundle`：retrieval card + source/reconstructed prompt + seconds-based timeline + compressed contact sheets + selected keyframes/dense evidence + audio text/events + analysis/eval。
2. **先 shot segmentation，再自适应抽帧。** 0.5s 只是漏检安全网；真正持久化由构图变化、动作阶段、物理接触、状态变化、运镜变化、图形变化、音频 onset、对白轮次和用户关注点驱动，并执行 perceptual dedup。
3. **秒数是主时间坐标。** 文件名与 timeline 用 `00.000s / 06.125s`，frame index 仅作隐藏技术字段。
4. **声音和画面共用一条 timeline。** 不只 ASR，还记录 speaker、speech style/prosody、BGM、SFX、ambience、beat/onset、AV sync；文字无法无损替代音色/混音，因此声音本身是 Golden 属性时允许例外保留紧凑原声证据。
5. **支持双向时间检索。** `time → description` 与 `description → time`，以及主体 `(start,end,caption)` 全轨迹。
6. **只有视频时可反推 Prompt，但必须叫 reconstructed_prompt。** 它能作为当前可执行候选和进一步迭代优化起点，不能伪装为历史 source prompt。
7. **三张因果图严格分离。** A 世界内物理因果；B 电影视听→观众理解因果；C Prompt control→output。单一观察视频通常只能支持 A/B 的观察性假设与 C 的 plausible hypothesis。
8. **Prompt 因果靠干预，不靠讲故事。** 冻结 model/version/mode/references/settings 等，只改主要变量做 A/B/C；控制污染则 `confounded`，不晋级。
9. **模糊召回从文字 retrieval card 开始。** 例如“时尚走秀那种”扩展为中英 aliases、task function、director goal、motion/camera/lighting/sound mechanisms，再取 1–3 个最高相关案例读取时间证据，不能要求 GitHub 自动理解所有图片像素后才能工作。
10. **评价按维度，不用一个总分。** 用户 verdict 是 Golden Case 权威；自动 eval 做身份、空间、动作、物理、声音、美学等诊断，并用后续真实生成校准。
11. **大规模案例库必须做视觉证据压缩。** shot contact sheet 优先于海量近重复单帧；关键瞬间再留独立高质量帧。Case ID 和 timeline 稳定，媒体存储层未来可迁移。
12. **案例多不等于学会物理规律。** 需要 sibling transfer、contrast、OOD、counterfactual 与 regression 把“会模仿相似案例”和“掌握可迁移机制”区分开。
13. **本项目的 Continual Learning 是外部经验学习，不声称修改闭源模型权重。** 通过 Retrieve → Adapt → Generate → Evaluate → Final-Delta → Retain 模拟专业生产中的 data flywheel。

当前保持 K3 / experiment：

- C-DANCE 2.5 的专有数据清洗、precise caption、reward 与 RLHF 配方；
- 不同类型镜头的最优自适应抽帧预算；
- 舍弃原视频后对细微运动加速度、motion blur、真实音色和混音信息造成的损失边界；
- 自动 aesthetic/physics grader 与用户导演判断的项目内校准曲线；
- 何时应从 GitHub 文本+图片索引升级到独立向量数据库；
- 当前 ChatGPT/GitHub 连接层对数千张图像的视觉向量检索覆盖，未实测前不得假装已具备。
