# 优秀提示词案例学习证据索引

> 本文件只保存 Golden Prompt Case Learning Protocol 的外部证据、术语映射、适用边界与再验证条件。操作规则见 `08_系统学习/优秀提示词案例学习协议.md`，不得在此建立第二份学习规则。

# 1. OpenAI contextual evals / golden set

- 来源：OpenAI，`How evals drive the next chapter in AI for businesses`，2025-11-19。
- 等级：E1/E2，官方方法论。
- 核心主张：evals 采用 `Specify → Measure → Improve`；领域专家应明确“great”是什么，并建立由真实输入到期望输出的 golden set；该集合应是领域专家判断与品味的 living authoritative reference；真实 inputs / outputs / outcomes 与专家 review 应形成持续 data flywheel。
- 项目转译：用户明确判定“优秀提示词”可成为 Golden Case 的权威触发，但案例登记与技能晋级必须分离。
- 边界：OpenAI 文档讨论通用 AI workflow，不是 Seedance 专用提示规范。
- 核验地址：https://openai.com/index/evals-drive-next-chapter-of-ai/

# 2. OpenAI 内部 Data Agent 的 Golden Answer + Unit Test

- 来源：OpenAI，`Inside OpenAI’s in-house data agent`。
- 等级：E2，官方真实工程案例。
- 核心主张：内部数据代理使用人工编写的 golden SQL 作为 reference；eval 不只做字符串匹配，还比较执行结果，并通过 grader 形成分数与解释；这些 eval 像持续运行的 unit tests，用于尽早发现 regression。
- 项目转译：优秀提示词案例既可作为 precedent，也可转成回归参考；但对开放式电影生成不能机械采用 exact-string match，需比较剧情功能、身份、空间、动作、连续性等目标维度。
- 核验地址：https://openai.com/index/inside-our-in-house-data-agent/

# 3. OpenAI Evals / Graders API

- 来源：OpenAI API Reference，Evals / Graders。
- 等级：E1，官方开发文档。
- 核心主张：eval 可把 data source schema 与 testing criteria 分离；grader 支持 string check、text similarity、label model、score model、Python grader、multi grader 等多种方式；score model grader 可接收 text / image / audio。
- 项目转译：Golden Case 不只存 prompt string，还应存可评价 schema；自动 grader 可以承担客观/半客观指标，但不能覆盖用户导演审美判断。
- 核验地址：
  - https://platform.openai.com/docs/api-reference/evals
  - https://platform.openai.com/docs/api-reference/graders

# 4. OpenAI model snapshot / version drift

- 来源：OpenAI API Reference，Backward compatibility。
- 等级：E1。
- 核心主张：不同模型 snapshot 的 prompting behavior 可能变化；官方建议 pin model version 并为应用建立 evals。
- 项目转译：Golden Case 必须尽量记录 model/version；模型大版本变化或提示行为漂移时，version-bound 技能进入 `needs_revalidation`，而不是把旧案例删除。
- 核验地址：https://platform.openai.com/docs/api-reference/backward-compatibility

# 5. Case-Based Reasoning（CBR）

- 来源：Aamodt & Plaza, `Case-Based Reasoning: Foundational Issues, Methodological Variations, and System Approaches`, AI Communications 7(1), 1994。
- 等级：E3，经典同行评议研究。
- 核心主张：case-based reasoning 通过历史案例进行检索、复用、修订与保留；经典工作通常概括为 Retrieve → Reuse → Revise → Retain。
- 项目转译：Golden Prompt Case 不是“提示词收藏夹”，而是可按任务相似度检索、适配、测试、再保留的新案例库。
- 边界：CBR 是通用推理框架，不直接说明 LLM 或视频模型的最佳检索算法。
- DOI：https://doi.org/10.3233/AIC-1994-7104

# 6. DSPy：从手工字符串转向 demonstrations + metrics + optimization

- 来源：Khattab et al., `DSPy: Compiling Declarative Language Model Calls into Self-Improving Pipelines`, arXiv:2310.03714。
- 等级：E3，研究论文 / 系统论文。
- 核心主张：传统 LM pipeline 常依赖人工试错得到的长 prompt string；DSPy 将 LM pipeline 表达为可参数化模块，并通过 demonstrations 与 metric 优化 pipeline。
- 项目转译：系统不应只学“这段字符串长什么样”，而应抽取 prompt 背后的可迁移结构，并让案例、metric、规则各自承担职责。
- 边界：DSPy 主要面向语言模型 pipeline；本项目借鉴其“程序/指标/示例分离”思想，不声称 Seedance 支持 DSPy 编译器。
- 核验地址：https://arxiv.org/abs/2310.03714

# 7. Reflexion：自然语言反馈 + episodic memory

- 来源：Shinn et al., `Reflexion: Language Agents with Verbal Reinforcement Learning`, arXiv:2303.11366 / NeurIPS 2023。
- 等级：E3。
- 核心主张：agent 可在不更新模型权重的情况下，把任务反馈转成语言反思并保存在 episodic memory buffer 中，改善后续 trial 的决策。
- 项目转译：用户对优秀/失败结果的自然语言评价可以形成外部记忆与后续推理条件；这与本项目 GitHub-first 的非权重 continual learning 路线相容。
- 边界：Reflexion 的任务环境与电影生成不同；只能作为架构类比，不是导演技能证据。
- 核验地址：https://arxiv.org/abs/2303.11366

# 8. Continual Learning / Experience Replay

## 8.1 Replay 缓解遗忘

- 来源：Rolnick et al., `Experience Replay for Continual Learning`, arXiv:1811.11682。
- 等级：E3。
- 核心主张：保存并回放历史经验可显著减轻 sequential learning 的 catastrophic forgetting；有限 buffer 也可通过样本选择保留代表性经验。
- 项目转译：Golden Case 作为经验回放库，可以防止系统只被最近一次提示词风格覆盖。
- 核验地址：https://arxiv.org/abs/1811.11682

## 8.2 Replay 不是越多越好

- 来源：Mahdaviyeh et al., `Replay can provably increase forgetting`, Proceedings of the 4th Conference on Lifelong Learning Agents, PMLR 330, 2026。
- 等级：E3。
- 核心主张：sample replay 的效果依赖任务结构与 replay sample 关系；在某些设置中 replay 甚至可能增加 forgetting。
- 项目转译：不能把所有优秀提示词全文注入每个任务；必须按相关性、边界与多样性选择案例，并监控 negative transfer。
- 核验地址：https://proceedings.mlr.press/v330/mahdaviyeh26a.html

# 9. Eval contamination / holdout reuse

## 9.1 OpenAI 2026 contamination lessons

- 来源：OpenAI，`A shared playbook for trustworthy third party evaluations`，2026-05-29；`Why SWE-bench Verified no longer measures frontier coding capabilities`，2026-02-23；`Separating signal from noise in coding evaluations`，2026-07-08。
- 等级：E1/E2。
- 核心主张：公开或重复使用的 benchmark 存在 contamination 风险；任务本身还可能 broken；自动 scoring 需要验证是否真正测到目标能力。
- 项目转译：如果同一个 Golden Case 已经直接作为 few-shot / retrieval 输入，就不能再把该案例本身的高分当成迁移能力证明，应建立 sibling / contrast / holdout cases。
- 核验地址：
  - https://openai.com/index/trustworthy-third-party-evaluations-foundations/
  - https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/
  - https://openai.com/index/separating-signal-from-noise-coding-evaluations/

## 9.2 Adaptive test reuse

- 来源：Feldman, Frostig & Hardt, `The advantages of multiple classes for reducing overfitting from test set reuse`, ICML 2019；Feng et al., `Sequential algorithmic modification with test data reuse`, UAI 2022。
- 等级：E3。
- 核心主张：持续根据同一测试集反馈修改系统会产生 adaptive dependence 与潜在过拟合风险，需要对重复测试的统计与流程风险保持警觉。
- 项目转译：高频用同一 Golden Case 调 prompt 时，应保留新的未直接参与优化的 transfer/holdout case。
- 核验地址：
  - https://proceedings.mlr.press/v97/feldman19a.html
  - https://proceedings.mlr.press/v180/feng22a.html

# 10. LLM-as-a-Judge 的 reference / calibration 风险

- 来源：Kranti & Vajjala, `LLM Judges Can Be Too Generous When There Is No Reference Answer`, arXiv:2607.12885, 2026。
- 等级：E3-preprint / candidate。
- 核心主张：所研究的 LLM judges 在缺少 reference answer 时更容易过度给分；加入 reference 会显著改变部分判定，作者建议先做 reference-aware calibration。
- 项目转译：自动 grader 对开放式电影提示词只作为辅助诊断；用户真实评价、生成结果与明确 reference 仍是高权重证据。
- 边界：该研究是语言评估，不是视频审美评估；不可直接量化迁移。
- 核验地址：https://arxiv.org/abs/2607.12885

# 11. 证据综合后的项目结论

当前可高置信采用：

1. Golden Case 应由用户/领域专家明确判断触发；
2. 案例本体与抽取技能应分开存储；
3. 原 prompt、上下文、版本与结果证据应保留 provenance；
4. Golden Case 应可作为 precedent 与 regression reference，但不能用同一直接检索案例独立证明泛化；
5. 自动 grader 适合作为多指标辅助，不应取代用户对导演质量的判断；
6. 模型版本变化要触发 revalidation；
7. 案例回放要相关、稀疏、多样，不能全量注入；
8. 单个优秀案例不能自动生成 general_stable 规则。

仍需项目真实验证：

- 哪些 Golden Case 检索维度最能提升 Seedance / Seedream 实际结果；
- 1、2、3 个案例 few-shot / precedent 的最佳数量；
- 不同模型版本对案例迁移的敏感度；
- 自动视觉/视频 grader 与用户导演评价的相关性；
- prompt-level excellence 与 output-level excellence 的一致程度。

以上未知项在出现真实生成数据前保持 candidate / experiment，不因为外部论文存在就升级为项目稳定规则。
