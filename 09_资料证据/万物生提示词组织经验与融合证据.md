# 万物生提示词组织经验与融合证据

> 本文件只保存用户提供的第三方学习总结、公开 Prompt 语料核验、与当前 AI电影系统的增量对照和候选验证方向。它不是第二套导演系统，不把二手总结冒充《万物生》原作者官方方法，不证明任何单一 Prompt 词必然导致某种生成结果。

# 1. 本轮来源与证据边界

## 1.1 用户提供的第三方学习总结

用户转述一位研究者在浏览《万物生》作者公开创作画布后形成的长篇经验总结。该总结提出一个压缩顺序：

```text
风格锁
→ 镜头总控
→ 素材分工
→ 音轨规则
→ 镜头事件
→ 结尾状态与限制
```

并进一步提出：

- 视频 Prompt 更像拍摄方案，而不只是画面描述；
- 抽象“手机感/电影感”应拆成可观察的成像特征；
- 摄影机运动应承担隐藏、确认、揭示等信息功能；
- 参考图需要职责分工，并可声明“不允许控制什么”；
- 动作应写出施力、方向、接触、身体反应、位移和环境反馈的因果链；
- 声音应与动作和空间同时设计；
- 每镜应明确可读的结束状态与下一镜接口；
- Prompt 长度不应成为目标，应按尚未由文字、参考图、故事板、视频、音频表达的控制缺口决定。

该文本本身属于 **secondary practitioner synthesis**。它不是模型官方规范，也不是本项目真实 Prompt→Output 对照实验。

用户文本中“这些动作因果描述可能是作者用 AI 辅助写的”属于个人猜测，本项目 **不登记为事实或技能依据**。

## 1.2 公开画布 Prompt 语料的二次存档核验

公开 GitHub 研究仓库：`Phantomlau3674/ai-film-director-workbench`，路径 `sources/neowow-wanwusheng/`。

该仓库自述来源页为 Neowow《万物生》公开作品页，并记录：

- 81 条 image prompts；
- 111 条有效 video prompts；
- prompt-only graph 362 nodes / 533 edges；
- 保留 raw prompt text；
- 不打包原媒体；
- `SUCCESS` 只表示任务返回成功，不代表艺术质量；
- 研究仓库自己的方法抽象不代表原作者认可。

因此该仓库可用于 **Prompt 组织结构与术语存在性** 的二次核验，但不能用于证明成片质量、模型稳定性或原作者主观方法论。

# 2. 实际抽查到的 Prompt 事实

本轮实际读取了该公开语料中的多条源 Prompt 样本。

## 2.1 样本 A

可观察字段包括：

- `style_lock`
- `reference_anchor`
- `timeline`
- `camera_geometry`
- `local_action`
- `composition`
- `visibility`
- `continuity`
- `transition`
- `negative_constraints`
- `color_semantics`
- `causal_trigger`
- `material_physics`

正文实际按“整体媒介/场景 → 时间段事件 → 整段运动控制 → 光影 → 风格 → 约束”等方式组织，并包含声音、手持呼吸感、局部动作和尾部转场压力。

## 2.2 样本 B

另一条真实 Prompt 的章节顺序为：

```text
场景空间关系
→ 运镜分段
→ 关键音效
→ 画面节奏
→ 人物动作连贯性约束
→ 视觉风格
```

这与“风格锁永远第一”的六步总结并不相同。

## 2.3 可确认与不可确认

可确认：

1. 《万物生》公开 Prompt 语料确实频繁把风格/媒介、摄影机、参考职责、时间事件、声音、连续性、约束和尾部状态组织成结构化执行包。
2. 相比只写人物剧情再补“电影感/环绕运镜”，这些 Prompt 更强调拍摄制度、摄影机—事件关系和多模态控制边界。
3. 源 Prompt 的字段顺序 **并非固定六步公式**；具体任务会调整顺序。

不可确认：

1. 不能说“《万物生》原作者统一使用固定六步法”。
2. 未检查对应原视频/参考图像素，不能说这些结构单独造成了优秀成片。
3. 不能由 prompt-only corpus 推出哪一个专业词拥有独立因果权重。
4. 不能确认动作细节由作者本人还是 AI 辅助撰写。

# 3. 与当前 AI电影系统的查重结果

## 3.1 已经存在，只记 SUPPORTS，不新增同义技能

### 动作因果链

当前 AI电影系统已有：

- 重要动作 = 预备 → 发生 → 结果 → 反应 → 余震；
- `EVENT-SEQUENCE-EXPLICIT-001`；
- SOAC / EventGraphIR 的 agent/action/target/instrument/support/contact/precondition/state change/result/reaction；
- `SCREEN-EVIDENCE-001` 的物理动作链。

因此“不要只写激烈打斗，要写力、方向、接触、身体反应和位移”只作为 SUPPORTS。

### 摄影机承担信息

当前最高原则已有“摄影机运动终点必须提供新信息”，CinematicIntentIR 已有 viewer position / attention flow / attention handoff。因此“摄影机先隐藏、再确认、再揭示”属于既有机制的良好外部例证，不新增第二规则。

### 声音参与叙事

当前 Sound Director / AudibleIR 已经把声音作为与画面平级的叙事层，并支持动作同步、画外空间、音频 onset 和声音连续性。因此只记 SUPPORTS。

### 结尾状态 / 下一镜接口

当前 `final_state`、TransitionContract、next-shot contract 已经是正式结构。因此“每镜知道最后停在哪里”只记 SUPPORTS。

### 最小充分 Prompt

当前 AI电影系统已经规定“内部分析复杂，模型执行稿最小充分”，参考图已锁定的信息不应无意义重复。因此“Prompt 长度取决于缺多少控制信息”与既有原则高度一致。

# 4. 真正值得保留的增量候选

以下均为 `candidate`。没有真实项目 A/B 前不晋级。

## 4.1 CAPTURE-REGIME-FEATUREIZATION-CANDIDATE｜风格/媒介特征化

### 问题

“手机感、纪录片感、电影感”这类抽象标签可能不足以让执行模型知道具体应出现哪些屏幕/声音证据。

### 候选机制

当媒介质感本身是交付关键时，把抽象 style/capture label 拆成 **少量、功能相关、可观察** 的成像与收音特征，而不是堆质量词。

例如“手机片场花絮感”可按当前需要从下列特征中选择子集：

- 竖屏或手机常见画幅；
- 广角近距离空间关系；
- 走路时轻微持握晃动/步态颠簸；
- 自动曝光小幅追随；
- 偶发短暂自动对焦漂移；
- 适量滚动快门；
- 广角边缘形变；
- 手机编码/压缩感；
- 手机麦克风动态和环境混杂声。

### 边界

- 不是把所有“缺陷”一次性堆满；
- polished cinema / 广告片不应为了所谓真实感被强行手机化；
- 每个特征仍服从剧情和摄影目的；
- 与 `MOTIVATED-CAPTURE-SUBSTRATE-001` 为 REFINES 关系，不建立第二套 capture authority。

## 4.2 REFERENCE-PERMISSION-BOUNDARY-CANDIDATE｜参考职责增加负权限边界

### 已有基础

项目已有六通道 reference authority 与 `REFERENCE-SIGNAL-DECOUPLING-002`。

### 新增候选

除“这张参考负责什么”，可进一步结构化：

```yaml
controls:
must_lock:
must_preserve:
must_not_control:
tolerated_variation:
```

例如：

```text
姿势参考只负责姿势与构图；
不得覆盖角色身份、服装和场景；
身份与服装继续由正式角色资产承担。
```

### 边界

- 自然语言写“不要控制”不是模型级权限系统，不能把它当魔法隔离；
- 若参考图的错误身份/纹理/光线信号非常强，仍可能需要 clean reference、white model、遮罩、分阶段生成或平台原生 reference controls；
- 不能让该候选覆盖正式资产和六通道 canonical authority。

## 4.3 MULTIMODAL-CONTROL-OWNERSHIP-CANDIDATE｜多模态信息所有权

### 核心问题

长 Prompt 可能只是重复了参考图、故事板、动作视频、白模和音频已经明确表达的信息，导致多通道争权、Prompt 负载上升和约束冲突。

### 候选机制

在最终 Prompt 编译前，对关键控制维度先分配最合适的 authority modality：

```text
身份 → 角色正式参考
空间几何 → 场景图 / 地图 / YAML / 白模
构图顺序 → storyboard / shot plan
动作轨迹 → action video / white model / text action contract
摄影机 → camera reference / white model / text camera contract
风格/材质 → style reference / quality master
声音 → audio reference / sound design
缺失绑定与关键因果 → text
```

文本优先承担：

- 各模态之间的职责绑定；
- 参考无法表达的动作因果；
- 关键不变量；
- 未表达的控制缺口；
- final state / transition contract。

### 边界

- “由参考承担”不等于该信息不重要；
- 当模型/平台的 reference reliability 不足时，关键不变量仍可以在文字中重复一次；
- Prompt 不是越短越好，而是 **未解决控制信息最少遗漏、已解决信息最少重复**。

与 `SCREEN-EVIDENCE-001`、SOAC、六通道 reference authority 为 REFINES / SUPPORTS 关系。

## 4.4 EXECUTION-PACKET-SERIALIZATION-CANDIDATE｜执行稿序列化而非导演顺序

用户转述的六段结构可保留为一种 **downstream execution packet serialization candidate**：

```text
GLOBAL capture / look contract
→ GLOBAL camera / movement contract
→ reference responsibility + permission boundaries
→ sound regime
→ shot / event blocks
→ final state + transition + hard constraints
```

但必须严格区分：

### 上游导演推理顺序仍然不变

```text
剧情目的
→ 观众当前知道什么
→ 人物目标与潜台词
→ 空间关系
→ 表演节拍
→ Blocking / 场面调度
→ 声音与剪辑
→ 摄影机
→ 模型与资产调用
```

### 下游执行稿可以把全局合同放前面

当导演决定已经完成后，为了让模型先读取全局规则，可以把 capture/look、camera regime、reference roles、sound regime 放在局部 shot/event 之前。

### 边界

- 不允许 STYLE LOCK / CAMERA LOCK 反过来决定人物为何行动；
- 不允许为了漂亮运镜修改 canonical Blocking；
- 实际字段顺序可按模型/任务变化，不能强制六步格式；
- 已有 storyboard 已承担构图与事件时，文字可以进一步缩短。

# 5. 负迁移扫描

不应机械迁移：

1. “所有视频都先 STYLE LOCK 再想人物行动”；
2. “越多手机缺陷越像手机”；
3. “每张参考都写大量禁止项”；
4. “所有动作必须拆到工程仿真级细节”；
5. “声音一定写在镜头事件之前”；
6. “六步顺序就是万物生原作者固定秘诀”；
7. “复杂英文摄影术语本身提高成片质量”；
8. “原作者的动作因果描述一定由 AI 辅助生成”。

# 6. Targeted Eval / Regression

已在 `11_验收/cinematic_visual_grammar_regression_cases.yaml` 增加候选：

- `REG-CAPTURE-REGIME-FEATUREIZATION-001`
- `REG-REFERENCE-PERMISSION-BOUNDARY-001`
- `REG-MULTIMODAL-CONTROL-OWNERSHIP-001`
- `REG-EXECUTION-PACKET-SERIALIZATION-001`

验证原则：

- 同剧情、同角色/场景/参考、同模型版本、同核心导演意图；
- 只改变目标结构变量；
- 对比 instruction following、跨模态污染、Prompt 负载、画面真实性、动作/空间/身份/声音保真、final state 和用户审美；
- 若多个变量一起变化，则只能记录组合效果，不能做单因果晋级；
- 真实生成前全部保持 `candidate`。
