# 学习应用与冲突裁决证据索引

> 本索引服务于 `10_运行时/learning_application_gate.yaml`。它保存外部理论与工程方法的来源、可迁移机制和边界，不替代 AI Film 自己的真实生成反馈，也不把外部理论直接晋级为项目稳定技能。

## 1. 研究目标

本轮要解决的不是“怎样多存几条规则”，而是四个运行问题：

1. 如何从用户对某个版本的评价中区分 **表面手段**、**真实导演目的** 与 **可能的因果机制**；
2. 当经验越来越多甚至互相矛盾时，如何按上下文、证据和版本让多个局部真理共存，并识别真正被证伪的旧结论；
3. 如何在不增加用户管理负担的前提下，主动提出信息量高、成本低的澄清问题或 A/B 验证；
4. 如何让已经学到且当前适用的经验，在下一次导演时真正成为输入与输出前验收条件，而不是只躺在知识库里。

## 2. 证据映射

### T2｜Explanation-Based Generalization / Purpose-directed concept learning

- Mitchell, Keller & Kedar-Cabelli (1986), *Explanation-Based Generalization: A Unifying View*。
- Kedar-Cabelli (AAAI 1987), *Formulating Concepts According to Purpose*。

可迁移机制：
- 学习不应只依靠表面相似，而应解释“为什么这个例子满足目标”。
- 同一个表面行为因目的不同可以拥有不同的有效抽象。
- 对 AI Film 的映射是：`妇女不能提前看到凯姆` 先作为局部手段保存，再追问/推断它服务的导演目的与机制；只有机制和条件经验证后才允许跨镜头复用。

边界：
- EBG 是机器学习经典方法论，不等于现代 LLM 已经自动实现可靠因果发现；项目仍需真实生成、反事实和回归。

### T2｜ATMS / Truth Maintenance

- Johan de Kleer (1986), *An Assumption-based TMS*。

可迁移机制：
- 不一致知识不必立即删掉其中一边；可把结论绑定到不同假设/上下文并维护依赖关系。
- 对 AI Film 的映射是：同一导演技巧在不同模型版本、场景功能、镜头类型或风险等级下可以同时成立。
- 冲突只有在“条件相同且不能同时成立”时才进入真正 contradiction / supersession 裁决。

边界：
- 本项目不实现完整 ATMS 推理机，只借用“上下文绑定 + 依赖/冲突关系 + 非破坏性修正”的治理原则。

### T2/T4｜Case-Based Reasoning / Agent experiential learning

- Aamodt & Plaza (1994) 的 CBR 框架强调 retrieve → reuse → revise → retain。
- Reflexion (NeurIPS 2023) 使用外部反馈形成语言化反思并保存为后续试验可调用的经验。
- A-MEM (NeurIPS 2025) 展示了把新记忆与既有记忆动态链接并允许记忆结构随新证据演化的方向。

可迁移机制：
- “保存经验”必须和“下一次检索、适配、修订、再保留”连成循环。
- 新记忆到来时应建立 SUPPORTS / BOUNDS / CONTRADICTS / SUPERSEDES 等关系，而不是孤立追加。
- 具体镜头 episode 与可迁移 procedure 必须分层。

边界：
- 外部 agent benchmark 的收益不能直接当作电影导演质量提升证据；这里只采用结构机制，创作效果仍由项目实测验证。

### T1/T4｜Episodic / Semantic / Procedural memory engineering

- LangChain / LangGraph 官方 memory 文档区分 semantic、episodic、procedural memory，并讨论 hot-path 与 background memory update。

可迁移机制：
- 具体镜头的“妇女不能提前看到凯姆”属于 episodic/work-item 约束。
- “近失误如何制造潜行悬念”属于更高层 semantic/procedural candidate。
- 防止 episodic tactic 无期限污染后续导演，是 Learning Application Gate 的必做项。

### T2｜Active Learning / Bayesian preference elicitation

- Active learning 研究把“应该问哪个问题”视为信息选择问题。
- Bayesian preference elicitation 的 pairwise comparison 研究强调低认知负担、价值信息量高的比较问题。
- 因果方向与干预式 active learning 研究强调用可区分假设的试验，而不是无控制地积累样本。

可迁移机制：
- 当系统在“用户是更重视悬念、写实、节奏还是隐蔽逻辑”之间无法判断时，应问一条能最大幅度区分候选意图的问题。
- candidate lesson 在自然低成本机会出现时，可以主动提供 A/B，帮助用户顺手完成验证。
- A/B 必须锁定会改变结果的关键变量，否则只能得到 `CONFOUNDED_INCONCLUSIVE`。

### T1｜OpenAI Evals / Graders

- OpenAI 官方 Evals / Graders 文档将质量要求表达为可重复的数据集、测试准则与 grader，而不是只依赖一次主观印象。

可迁移机制：
- 已学到的规则要进入 regression / pre-output checks。
- Learning Application Gate 的价值不是再生成一份长总结，而是把“当前适用的学习”转成这次交卷前必须过的检查项。

边界：
- 创作质量不能被单一自动 grader 完整覆盖；用户审美判断、剧情目的和真实视频结果仍是核心证据。

### T3｜Hitchcock suspense / 观众信息设计

- Hitchcock 在 MoMA 收录访谈中区分 surprise 与 suspense，核心之一是观众提前掌握危险信息后产生持续期待。
- 后续 suspense 研究显示“悬念”不能简单等同于单一的不确定性变量，观众立场、后果重要性和信息结构都会改变效果。

可迁移机制：
- `妇女不能提前看到凯姆` 的更高层学习不应是“配角永远不能看见主角”，而应是：在侦查/潜行场景中，让观众清楚读懂暴露风险、可能后果和近失误，从而维持期待与紧张。
- 可以用开窗、声音、影子、巡逻者回头、环境反应等不同手段实现同一目的。

边界：
- “近失误 = 一定有悬念”不是稳定定律；必须结合角色立场、风险后果、观众信息状态与节奏。

### T1｜ByteDance Seedance 官方资料

- Seedance 官方资料强调复杂动作、多镜头叙事、提示遵循、运动与视觉质量等多个维度；模型能力与行为还会随版本变化。
- Seedance 技术资料的多维训练/评估思路支持项目把“B 比 A 好”拆成构图、动作、时序、指令遵循、物理合理、表演等维度，而不是只存一个总分。

可迁移机制：
- 模型行为经验必须绑定 model/tool/version。
- 一个维度改善不能自动推导所有维度改善。
- 模型升级后旧版本经验进入 `needs_revalidation`。

## 3. 项目采用的综合结论

本项目采用：

`Episode Evidence → Intent → Mechanism → Contextual Policy → Transferable Principle`

并用：

`Context + Evidence Quality + Maturity + Version + Counterexample + User Intent`

裁决经验冲突。

这意味着：
- 保存“发生了什么”；
- 解释“为什么用户更喜欢/为什么结果更好”；
- 对因果归因保留替代解释；
- 给每条经验明确 scope、expiration、confidence vector、failure conditions；
- 条件不同的冲突允许共存；
- 条件相同且新证据更强时才做 supersession；
- 无法裁决时主动问最小必要问题；
- 未验证 candidate 等待低成本自然机会做 A/B；
- 每次导演前与交卷前都经过 Learning Application Gate。

## 4. 尚未被外部证据解决的问题

- 创作审美目标往往是多目标且会随剧情阶段变化，无法用固定单一 reward 替代用户判断。
- LLM 对“真正因果机制”的自然语言解释仍可能是合理化而非真实因果，因此项目必须保留反事实、控制变量、真实生成和用户复核。
- 大规模学习库增长后的检索召回率、冲突发现率和 latency 尚需项目内压力测试。
- ChatGPT Project 是否在每一轮真实执行 GitHub `read_sets` 与 gate，需要单独的 invocation / observability 验证，不能仅由文件存在推断。
