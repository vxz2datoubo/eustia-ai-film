# 主动协作与成本路由证据索引

> 本文件只承担“下一步交付机会扫描 / 主动协作 / 成本感知模型级联”的外部证据职责，不覆盖项目剧情、角色、场景、资产或导演美学 canonical。

## 1. 项目内触发证据

### OBS-NEXT-STEP-001｜H3低成本测试后的主动交付建议

- 日期：2026-08-15
- 场景：`KAIM-HIGH-SEARCH-30S` 的 7 秒窗口动作 A/B 修订。
- 用户明确说明：C-DANCE 2.5 成本较高，今后小测试可先使用 MiniMax H3，因为此前 A/B 在不同模型中的运动轨迹具有较高相似性，而 H3 成本低很多。
- 助手随后主动提出：既然本轮实际下游执行模型已经变成 MiniMax H3，就应继续把当前 A/B 方案编译成 H3 专用执行稿，而不是让用户再次开口要求格式转换。
- 用户明确评价这一主动联想“非常好”，并要求研究其触发机制、让以后更多出现这种做法。
- 证据等级：`user_explicit_positive_feedback / scene_verified_observation`。
- 可复用规则成熟度：`candidate`，因为一次积极反馈不足以证明所有主动建议都有效。

## 2. 外部研究基础

### EVID-MIXED-INITIATIVE-001｜Microsoft Research：Mixed-Initiative Interaction

- 来源：Eric Horvitz, *Uncertainty, Action, and Interaction: In Pursuit of Mixed-Initiative Computing*, Microsoft Research / IEEE Intelligent Systems, 1999。
- 相关结论：高价值人机协作不必在“完全自动化”与“完全由用户直接操作”之间二选一；系统可以结合对用户活动、目标与不确定性的理解，在合适时机提供自动服务，同时保留人的控制权。
- 项目用途：支持“不是只等用户逐条命令，而是在高置信、低风险、明显减摩擦时主动补下一步”的方向。
- 边界：这是通用 HCI / mixed-initiative 原则，不直接证明本项目某个具体触发器必然有效。
- URL: https://www.microsoft.com/en-us/research/publication/uncertainty-action-interaction-pursuit-mixed-initiative-computing/

### EVID-MIXED-INITIATIVE-002｜Microsoft Research：Principles of Mixed-Initiative User Interfaces

- 来源：Eric Horvitz, CHI 1999。
- 相关结论：混合主动式系统需要决定何时介入、何时询问、如何表达不确定性，并将自动服务与用户直接控制优雅结合。
- 项目用途：为“高置信直接补交付、中置信只建议、低置信不打扰”的 intervention gate 提供理论依据。
- URL: https://www.microsoft.com/en-us/research/publication/principles-mixed-initiative-user-interfaces/

### EVID-PROACTIVE-ASSISTANT-001｜Microsoft Research：Need Help? Designing Proactive AI Assistants for Programming

- 来源：Chen et al., CHI 2025。
- 相关结论：聊天助手可由纯反应式转向在共享工作上下文中主动提供建议；研究同时表明主动帮助的价值与其介入设计、相关性和用户体验边界有关。
- 项目用途：支持项目在明确共享上下文中主动识别高价值下一步，但必须限制无关或高摩擦建议。
- URL: https://www.microsoft.com/en-us/research/publication/need-help-designing-proactive-ai-assistants-for-programming/

### EVID-COST-ROUTING-001｜FrugalGPT

- 来源：Chen, Zaharia, Zou, *FrugalGPT: How to Use Large Language Models While Reducing Cost and Improving Performance*, 2023。
- 相关结论：不同模型存在显著成本/能力差异，可采用 prompt adaptation、模型近似和 LLM cascade 等策略，用便宜路径优先处理、必要时再升级到强模型。
- 项目用途：为“低成本模型先做动作/轨迹/结构筛查，高成本模型承担最终高保真验证”的两阶段生成策略提供工程类比。
- 边界：论文研究对象主要是 LLM，不直接证明 MiniMax H3 与 C-DANCE 2.5 的视频质量关系；具体视频级联仍需项目实测。
- URL: https://arxiv.org/abs/2305.05176

### EVID-COST-ROUTING-002｜RouteLLM

- 来源：Ong et al., *RouteLLM: Learning to Route LLMs with Preference Data*, 2024。
- 相关结论：可按任务与成本/质量权衡动态选择较强或较弱模型，而不是所有请求固定使用最昂贵模型。
- 项目用途：支持建立“测试目的 → 最低充分模型 → 最终验证模型”的成本感知路由思想。
- 边界：同样属于跨模型工程启发；不能将其结果直接外推为 H3 与 C-DANCE 的能力结论。
- URL: https://arxiv.org/abs/2406.18665

## 3. 当前证据结论

当前足以支持的 candidate 方向：

1. 当用户已经明确下游工具/模型、执行目的和成本约束时，系统应扫描是否存在一个低风险、显著减少用户重复操作的“下一步交付物”。
2. 当当前产物需要确定性的格式/适配转换才能进入用户已明确的下游工具，且适配规则已知时，可主动提供 native 交付，而不是等待用户再次要求。
3. 对昂贵模型的验证任务，可在不改变测试目标的前提下优先考虑便宜模型/短时长/低成本 probe；但代理模型与正式模型的相关性必须由真实项目证据逐步验证。
4. 主动建议必须经过介入门槛：高相关、高置信、低风险、明显节省成本或操作；否则保持安静或只做简短建议。
5. H3、C-DANCE、Seedream、Suno 等具体执行语法仍由各自 adapter / 专用知识源负责；下一步机会扫描只负责“何时应该主动切换/编译/补交付”，不复制模型私有规则。
